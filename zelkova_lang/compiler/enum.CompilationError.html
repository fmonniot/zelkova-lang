Expand description

Every way compiling a package can fail, tagged with the phase that failed.

Each phase-carrying variant holds all the errors that phase produced for one module rather than only the first, plus the module’s Name, which is what as_diagnostic puts in front of the message. Rendering goes through PhaseError; see that trait for why no variant here carries a span.

InFile(Box<CompilationError>, SourceFileId)

An error together with the file the module it belongs to was read from.

A phase never knows its SourceFileId, so the labels its errors produce are byte ranges with no file attached. This is where the two halves are put together, and it has exactly one constructor: compile_package, which is the only place that knows which file a module was parsed from. Nothing else should build it — an id guessed anywhere else would underline the wrong file.

§

Many(Vec<CompilationError>)

Every error accumulated over one compilation pass.

compile_package does not stop on the first failure: it keeps going so that one broken module cannot hide the diagnostics of the others. This variant is how that accumulation becomes a failure again at the end of the pass, with the typed errors still intact for the caller to inspect.

pub fn as_diagnostic(&self) -> Diagnostic<SourceFileId>

Turn this error into the diagnostic the user reads.

This is the compiler’s single rendering point — compile_package calls it and nothing else builds a Diagnostic from a phase error. It is public so that a test can assert on what the user is actually shown, rather than on is_err(): what a failure says is the behaviour this method exists for.

Source

pub fn module(&self) -> Option<&Name>

The name of the module this error belongs to, when it has one.

compile_package uses it to look up the file the module was read from, which is how an InFile wrapper gets its id.
