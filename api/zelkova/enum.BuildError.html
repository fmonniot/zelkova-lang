Expand description

Every way building a package can fail: its check, or emitting, writing or running what checked.

The check’s own errors are CompilationErrors, each wrapped in Check; the other variants are what only a build can raise.

Variants§

§

Check(CompilationError)

An error of the check. On its own — returned rather than accumulated — it is one raised before there was a build to check, the root’s manifest or the resolution of its dependencies, and is unrendered.

§

Emit(Vec<Error>, Name)

The named module checked and could not be emitted as JavaScript.

§

Output(Error)

A file of the build’s output could not be written. Raised only once every module of the build has checked and emitted, since nothing is written before that.

§

TestRun(Error)

A package’s tests were compiled and could not be run: zelkova test could not write its entry point or could not run node. A test that ran and did not pass is not this; it is the exit code of the run.

§

ProgramRun(Error)

A package’s program could not be run: zelkova run was pointed at a package with no main, or could not write its entry point or could not run node. A program that ran and aborted is not this; it is the exit code of the run.

§

InFile(Box<BuildError>, SourceFileId)

An Emit together with the file its module was read from, so that its labels have a file to point into. It wraps nothing else: an error of the check carries its own file inside Check, as a CompilationError::InFile.

§

Many(Vec<BuildError>)

Every error a build accumulated, each already rendered to stderr.

Flat: each error of the check is one Check member, and a CompilationError::Many is never wrapped — its members are. A build does not stop on the first failure, so that one broken module cannot hide the diagnostics of the others; this is how that accumulation becomes a failure again at its end, with the typed errors still intact for the caller to inspect.
