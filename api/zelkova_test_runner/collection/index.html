Collecting a package’s tests.

A test is a value a module under tests/ exposes whose type is zelkova-test’s Test — What a test is. This module is the pass that finds them: given the Interfaces of the modules of a package’s tests/ root that checked, collect returns, per module, the sorted names of the values that have that type.

It does not run anything, and does not decide how a runner reports what it finds — that is zelkova_test_runner’s, the only caller this one is written for.

§Identified by type, never by spelling

Test is found by its full QualName — package, module and name — the same way a Scalar is (DEC-15 decision 1 is that precedent). A package that declares its own Test type does not get its values run: MyPackage.Test and zelkova-test:Test.Test are two different declarations that happen to share a spelling, and only a whole-QualName comparison tells them apart. A package that does not depend on zelkova-test at all simply has nothing that can carry the type, so collect finds nothing in it and raises no error over that.
