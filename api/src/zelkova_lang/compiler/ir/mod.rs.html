1//! The intermediate representation code generation reads.
2//!
3//! The typer produces it. It is the only phase that knows a node's type, and every node
4//! here carries one ([`DEC-18` decision
5//! 1](../../../docs/decisions/dec-18.md#1--the-backend-reads-a-typed-ir-and-the-typer-is-what-produces-it)).
6//! [`Term`] is the untyped half — what the translation from the canonical AST builds —
7//! and [`TypedTerm`] is the same tree once inference has solved a type for each of its
8//! nodes. A [`Module`] holds the unions a module declares and one [`Declaration`] per
9//! value: everything about a module that only emission asks for.
10//!
11//! It is not the whole of what a backend is handed. `check_module` answers with a
12//! [`CheckedModule`](crate::compiler::CheckedModule), which is this beside the
13//! [`canonical::Module`] it was built from, and two of the things emission needs are
14//! still only on that half — a module's `exports`, which is what a JavaScript module has
15//! to export, and `canonical::Value::TypedValue`'s `marked_unsafe`, which
16//! [`javascript::emit`](crate::compiler::javascript::emit) reads because an `unsafe`
17//! signature and an effectful one emit differently. Nothing here duplicates them.
18//!
19//! The type language itself is still [`typer::Type`](crate::compiler::typer::Type). It is
20//! the typer's own representation and unification is written against it, so it stays
21//! there; this module names it and adds nothing to it.
22//!
23//! # What this shape owes WebAssembly
24//!
25//! One IR serves both targets and JavaScript is written first ([`DEC-18` decision
26//! 2](../../../docs/decisions/dec-18.md#2--one-ir-serves-both-targets-and-javascript-is-written-first)),
27//! so a reader arriving while only the JavaScript backend exists will find things
28//! JavaScript has no use for. None of them is spare:
29//!
30//! - **A type on every node.** JavaScript needs almost none of them: the canonical AST
31//!   already separates an `Int` literal from a `Float` one, and arithmetic and equality
32//!   are ordinary functions behind facades. WebAssembly is statically typed, and a node's
33//!   representation class — an `i64`, an `f64`, a reference — is read off its type.
34//!   Solved types are also what monomorphisation consumes, which is the only way
35//!   polymorphism reaches a target where [a class dictionary is erased by specialisation
36//!   and never
37//!   passed](../../../docs/decisions/dec-2.md#7--dictionaries-are-erased-by-specialisation-not-passed).
38//! - **A constructor's index within its declaration**, and not only its name. A union is
39//!   a WIT `variant` with one case per constructor and a tuple is a `tuple` ([A union
40//!   crosses as a tagged
41//!   value](../../../docs/spec/interop.md#a-union-crosses-as-a-tagged-value)), so a
42//!   constructor is reached by its position there. JavaScript writes the name into the
43//!   `$` field and never asks for the index.
44//! - **Arity as a fact and saturation per call site.** A declaration emits as a plain
45//!   n-ary function on both targets ([`DEC-18` decision
46//!   3](../../../docs/decisions/dec-18.md#3--a-function-emits-as-a-plain-n-ary-function-and-currying-is-a-runtime-helper)),
47//!   and a facade's [plain parameter
48//!   list](../../../docs/spec/interop.md#the-javascript-companion) is the same call shape
49//!   either way. WebAssembly has no closure primitive, so how a partial application is
50//!   represented there is open — and an IR that made a call site's saturation something
51//!   to re-derive would make that question harder rather than leaving it open.
52//!
53//! [`GEN-15`](../../../docs/tickets/gen-15.md) holds the questions a WebAssembly backend
54//! still has to answer — linear memory or WasmGC, how a partial application is
55//! represented, whether monomorphisation is whole-program — and is unscheduled. Nothing
56//! in this module is a JavaScript decision, and a change that makes one of the four
57//! facts above unavailable is a change that closes that ticket's options.
58//!
59//! # What is not here yet
60//!
61//! One ticket adds a mark to this shape and is deliberately not written into it yet: a
62//! self tail call ([`GEN-6`](../../../docs/tickets/gen-6.md)). [`Module`] holds its
63//! declarations in a `Vec` sorted by name, which is a deterministic order and not an
64//! evaluation order; [`Module::initialisation_order`] is the evaluation order, over the
65//! parameterless ones alone, and [`javascript::emit`](crate::compiler::javascript::emit)
66//! emits them in it.
67//!
68//! A `case`'s branches keep [`TypedTermKind::Case`]'s own flat shape rather than
69//! growing a tree in place: the typer still wants a flat list, since every branch is
70//! checked against the same scrutinee type and order does not matter to it. The
71//! `decision` module is a second, additional view of the same branches — built from
72//! them on demand rather than stored alongside them — and [`Decision`] is the tree a
73//! backend walks instead of re-deriving, at emission time, which test distinguishes
74//! which branch (`GEN-5`). See that module's doc comment.

90/// One checked module's emittable shape: what a backend reads that no earlier phase
91/// carried.
92///
93/// Not everything emission needs — `exports` and `marked_unsafe` stay on the
94/// [`canonical::Module`] this was built from, and a backend is handed both halves as a
95/// [`CheckedModule`](crate::compiler::CheckedModule). See this module's doc comment.
96#[derive(Debug)]
97pub struct Module {
98    pub name: ModuleName,
99    /// True when this module is a `module foreign` facade: every one of its
100    /// declarations is a signature with no body, and the code behind them is in the
101    /// companion beside it ([Foreign
102    /// interoperability](../../../docs/spec/interop.md)).
103    pub foreign: bool,
104    /// The unions this module declares, sorted by name.
105    pub unions: Vec<Union>,
106    /// The declarations this module can emit, sorted by name.
107    ///
108    /// Sorted so that two runs of the compiler over one unchanged module produce the
109    /// same order — `canonical::Module::values` is a `HashMap` and yields none. It is
110    /// not an evaluation order: [`initialisation_order`](Self::initialisation_order) is
111    /// what works out which parameterless declaration has to be initialised before which.
112    pub declarations: Vec<Declaration>,
113    /// The declarations that have no IR, and therefore cannot be emitted.
114    ///
115    /// A backend handed only [`declarations`](Self::declarations) could not tell a module
116    /// it may emit whole from one that quietly lost a declaration on the way here, which
117    /// is the mistake [`DEC-18` decision
118    /// 1](../../../docs/decisions/dec-18.md#1--the-backend-reads-a-typed-ir-and-the-typer-is-what-produces-it)
119    /// is about. Every value of the canonical module is in one list or the other.
120    pub unchecked: Vec<Unchecked>,
121    /// The names of [`declarations`](Self::declarations) that take no parameter, in the
122    /// order they must be initialised: each only after every parameterless declaration its
123    /// own body mentions
124    /// (`docs/spec/evaluation-semantics.md#a-binding-with-no-parameters-is-evaluated-once`).
125    /// Empty for a module whose declarations all take parameters, and for a `module
126    /// foreign` facade, whose constants are evaluated on whatever schedule the target
127    /// gives them (`docs/spec/interop.md#facade-constants`).
128    ///
129    /// Sorted so that two runs of the compiler over one unchanged module produce the same
130    /// order, same as [`declarations`](Self::declarations) above — including among
131    /// bindings with no edge between them, where a topological sort alone leaves the order
132    /// unconstrained.
133    ///
134    /// [`canonical::initialisation_order`] computes it, reusing the dependency graph
135    /// `canonical::canonicalize` already built to reject a cycle (`LANG-35`) rather than
136    /// building a second one from the same rule; see that function's doc comment for the
137    /// acyclic assumption this relies on and which phase discharges it.
138    /// [`javascript::emit`](crate::compiler::javascript::emit) is what emits declarations
139    /// in this order — this only computes it.
140    pub initialisation_order: Vec<Name>,
141}

168/// One value of a module: what a backend emits as a named binding.
169#[derive(Debug)]
170pub struct Declaration {
171    pub name: Name,
172    /// How many arguments a call site has to supply for the call to be a direct call.
173    ///
174    /// For a declaration with a body this is the number of parameters it was written
175    /// with, which is [`Body::parameters`]'s length — *not* the number of arrows in its
176    /// type. `f : Int -> Int -> Int` written `f a = add a` has arity 1, and a call
177    /// supplying two arguments is one direct call followed by one partial application.
178    ///
179    /// For a facade signature, which has no body to count parameters off, it is the
180    /// number of arrows in the signature: the companion's export [takes a plain parameter
181    /// list](../../../docs/spec/interop.md#the-javascript-companion) of exactly that
182    /// length, and a signature with no arrow at all is [a facade
183    /// constant](../../../docs/spec/interop.md#facade-constants).
184    pub arity: usize,
185    /// The declaration's own type, as inference solved it — or, for a facade, as the
186    /// signature declares it.
187    pub tpe: Type,
188    /// The parameters and the expression they are in scope over, for a declaration that
189    /// has a body.
190    ///
191    /// `None` is a `module foreign` facade's signature. It is the whole reason this is an
192    /// `Option`: a facade declares what crosses the boundary and the code is in the
193    /// companion, so there is nothing here to emit and
194    /// [`javascript::emit`](crate::compiler::javascript::emit) reads the signature
195    /// instead.
196    pub body: Option<Body>,
197    /// Where the declaration was written, annotation and body together.
198    pub span: NodeSpan,
199}

228/// A reference to a name, and what kind of name it is.
229///
230/// The kind is the point. `canonical::ExpressionKind` distinguishes a local, a
231/// top-level, an imported name and a constructor, and those are four different things to
232/// emit — a parameter, a binding in this module's scope, a named import, an object with
233/// a `$` field. The spelling left behind once they are flattened to a string is
234/// qualified for some of them and not others, so the distinction cannot be recovered
235/// afterwards.
236#[derive(Debug, Clone, PartialEq)]
237pub struct Reference {
238    /// The spelling inference looks the name up by.
239    ///
240    /// The typer's environment is a `HashMap<String, Type>` keyed by the spelling the
241    /// canonical AST carries — bare for a local, qualified for everything else — so this
242    /// is that key and not a display name. A backend reads [`kind`](Self::kind), which
243    /// says what the name *is*.
244    pub name: String,
245    pub kind: ReferenceKind,
246}
247
248impl Reference {
249    /// A reference to a name bound inside the declaration: a parameter, or a name a
250    /// pattern introduced.
251    pub fn local<S: Into<String>>(name: S) -> Reference {
252        Reference {
253            name: name.into(),
254            kind: ReferenceKind::Local,
255        }
256    }
257}

259/// Which of the four things a [`Reference`] names.
260#[derive(Debug, Clone, PartialEq)]
261pub enum ReferenceKind {
262    /// A parameter of the enclosing declaration, or a name one of its patterns bound.
263    /// It is in scope for that declaration alone.
264    Local,
265    /// A declaration of the module being compiled, named in full.
266    TopLevel(QualName),
267    /// A declaration of another module, named in full: a named import of whatever that
268    /// module emitted.
269    ///
270    /// The typer checks it against the type that module's interface declares.
271    Foreign(QualName),
272    /// A union constructor: it builds a tagged value rather than reading a binding.
273    Constructor(Constructor),
274}

276/// A constructor, and its place in the declaration that declares it.
277///
278/// Both targets need all four: the name is the `$` field's value and the WIT case name,
279/// the index is the case's position in the `variant`, the arity says how many arguments
280/// a saturated application supplies, and the union is which declaration the case belongs
281/// to.
282#[derive(Debug, Clone, PartialEq, Eq)]
283pub struct Constructor {
284    /// The union this constructor builds, named by the module that declared it.
285    pub union: QualName,
286    /// The constructor's own name, unqualified.
287    pub name: Name,
288    /// Its position in that union's declaration, counted from zero.
289    pub index: usize,
290    /// How many arguments it takes.
291    pub arity: usize,
292}

294/// Whether an application supplies every argument its callee takes.
295///
296/// A saturated application at a callee whose arity is known emits as a direct call;
297/// everything else goes through the runtime's `$curry` helper ([`DEC-18` decision
298/// 3](../../../docs/decisions/dec-18.md#3--a-function-emits-as-a-plain-n-ary-function-and-currying-is-a-runtime-helper)).
299/// An [`Apply`](TermKind::Apply) node supplies one argument, so this is a property of a
300/// node within the application spine and not of the spine as a whole: `f a b` at a
301/// two-parameter `f` is [`Partial`](Saturation::Partial) on the inner node and
302/// [`Saturated`](Saturation::Saturated) on the outer one.
303#[derive(Debug, Clone, Copy, PartialEq, Eq)]
304pub enum Saturation {
305    /// This node supplies the last of the arguments the callee takes.
306    Saturated,
307    /// It does not — either because arguments are still missing, because the spine has
308    /// already run past the callee's arity, or because the callee's arity is not known
309    /// here at all. A callee that is a parameter is a value rather than a declaration and
310    /// has no arity; an imported one has an arity this module cannot see.
311    Partial,
312}

378/// What the source wrote that a `Case` term was built from.
379///
380/// A parameter written as a pattern — `first (x, _) = x` — is a match like any other,
381/// and it is translated as one: the parameter becomes a plain one named by
382/// [`pattern_parameter`], and the declaration's body a single-branch `Case` on it. So a
383/// backend lowers a pattern in either position the same way, and the term language keeps
384/// one binding construct, [`TermKind::Fun`], that only ever binds a name.
385///
386/// This is what lets a diagnostic about the match speak about what the user wrote: a
387/// type error in a parameter's pattern names the parameter and not a `case`, one in the
388/// body under it names the declaration's body and not a `case` branch, and a
389/// backend refusing the match can say which of the two it is refusing.
390#[derive(Debug, Clone, Copy, PartialEq, Eq)]
391pub enum CaseForm {
392    /// A `case … of` expression.
393    Expression,
394    /// A parameter the declaration wrote as a pattern. The `Case` has exactly one
395    /// branch, and its scrutinee is the local reference [`pattern_parameter`] names.
396    Parameter,
397}
398
399/// The name a parameter written as a pattern is bound under: `$` and the parameter's
400/// position in the declaration, counted from zero — `$0`, `$1`, ….
401///
402/// It is the scrutinee of the [`CaseForm::Parameter`] match the parameter becomes, and
403/// nothing else refers to it. It cannot meet a name the source wrote, because a Zelkova
404/// identifier never contains a `$`, and it cannot meet another parameter's, because two
405/// parameters of one declaration never share a position. A declaration's parameters are
406/// the only names its body is in scope of besides the ones a pattern binds, which are
407/// source names, so that is every name it could meet.
408pub(crate) fn pattern_parameter(position: usize) -> String {
409    format!("${}", position)
410}

412/// Simplified pattern used inside a [`Term`], and where it was written.
413///
414/// Same shape as the parser and canonical ASTs — a span beside a kind — so a reader
415/// matches on `&p.kind`.
416#[derive(Debug, Clone)]
417pub struct TermPattern {
418    pub span: NodeSpan,
419    pub kind: TermPatternKind,
420}

422#[derive(Debug, Clone)]
423pub enum TermPatternKind {
424    /// Matches anything without binding.
425    Anything,
426    /// Binds the scrutinee type to this name.
427    Bind(String),
428    /// Matches one specific value; constrains the scrutinee to the type carried here
429    /// and, unlike the type alone, says which value of it.
430    ///
431    /// `tpe` is a [`Type::Literal`] for an `Int` or a `Char` pattern, and the
432    /// [`Type::Adt`] `typer::bool_type` builds for a `true`/`false` or a `True`/`False`
433    /// one — `Bool` is the union `Basics` declares, not a literal type. Two patterns of that same kind — two
434    /// `Int`s, say — share that one type, so `value` is what tells `1` from `2`, or
435    /// `true` from `false`; [`decision_tree`] reads it to build the [`Outcome`] a
436    /// [`Decision::Test`] checks for.
437    Literal { tpe: Type, value: LiteralValue },
438    /// Matches an ADT constructor; carries the fresh ADT args and one sub-pattern per
439    /// argument.
440    Constructor {
441        /// Which constructor, and where it sits in its declaration. `ctor.union` is the
442        /// name the [`Type::Adt`] this pattern constrains the scrutinee to is built from.
443        ctor: Constructor,
444        adt_args: Vec<Type>,
445        /// One per argument the pattern writes, in order, so an argument's place in
446        /// this `Vec` is its position in the constructor.
447        args: Vec<SubPattern>,
448    },
449    /// Matches a tuple of two or three elements; carries one sub-pattern per element.
450    Tuple {
451        /// One per element, in order. The matched value's tuple type is built from
452        /// their types.
453        elements: Tuple<SubPattern>,
454    },
455}
456
457/// A pattern written in a position inside another one — a constructor's argument or a
458/// tuple's element — and the type of the value found there.
459///
460/// The position's type travels with the pattern because a sub-pattern has no scrutinee
461/// of its own to take one from: a variable written there binds a value of this type, and
462/// any other pattern written there constrains this type the way a `case` branch's
463/// pattern constrains the scrutinee's.
464///
465/// Today the pattern is only ever a [`TermPatternKind::Bind`] or a
466/// [`TermPatternKind::Anything`]: `typer::translate_pattern` refuses anything nested
467/// deeper (`LANG-16`). The shape does not assume it.
468#[derive(Debug, Clone)]
469pub struct SubPattern {
470    pub tpe: Type,
471    pub pattern: TermPattern,
472}
473
474impl TermPattern {
475    /// Every name this pattern binds, at any depth, in source order, with the type of
476    /// the value it binds. A variable written at the top is bound at `scrutinee`, the
477    /// type of the value the pattern is matched against.
478    pub(crate) fn bindings(&self, scrutinee: &Type) -> Vec<(String, Type)> {
479        let mut bindings = Vec::new();
480        self.collect_bindings(scrutinee, &mut bindings);
481        bindings
482    }
483
484    fn collect_bindings(&self, tpe: &Type, bindings: &mut Vec<(String, Type)>) {
485        match &self.kind {
486            TermPatternKind::Anything | TermPatternKind::Literal { .. } => {}
487            TermPatternKind::Bind(name) => bindings.push((name.clone(), tpe.clone())),
488            TermPatternKind::Constructor { args, .. } => {
489                for arg in args {
490                    arg.pattern.collect_bindings(&arg.tpe, bindings);
491                }
492            }
493            TermPatternKind::Tuple { elements } => {
494                for element in elements.iter() {
495                    element.pattern.collect_bindings(&element.tpe, bindings);
496                }
497            }
498        }
499    }
500}

502/// The concrete value a [`TermPatternKind::Literal`] pattern tests for.
503///
504/// The pattern's own `tpe` cannot tell `1` from `2`, or `'a'` from `'b'`: both share one
505/// type, and only this says which value the scrutinee has to equal. A `Bool` is tested
506/// by its value whichever spelling the pattern used: `true`/`false` and `Basics`' own
507/// `True`/`False` constructors both arrive here as a `Bool(..)`, never as a
508/// [`TermPatternKind::Constructor`] (`typer::translate_pattern` does the normalising).
509#[derive(Debug, Clone, Copy, PartialEq, Eq)]
510pub enum LiteralValue {
511    Bool(bool),
512    Int(i64),
513    Char(char),
514}

566    Let {
567        binding: TypeBinder,
568        value: Box<TypedTerm>,
569        body: Box<TypedTerm>,
570    },
571    Tuple(Tuple<TypedTerm>),
572    Case {
573        scrutinee: Box<TypedTerm>,
574        branches: Vec<(TermPattern, Box<TypedTerm>)>,
575        /// See [`TermKind::Case`].
576        form: CaseForm,
577    },
578}

580// ── What the typer answers with ───────────────────────────────────────────────
581
582/// What the typer has to say about one declaration.
583///
584/// A phase that answers with types has to answer for *every* declaration it was given,
585/// including the ones it could not type: a caller handed only the ones that worked
586/// cannot tell a declaration the typer verified from one it walked past, and emitting
587/// code for the second is a miscompile. So the three ways a declaration goes untyped
588/// each get a variant, and [`typer::type_check`](crate::compiler::typer::type_check)
589/// returns one entry per declaration either way.
590#[derive(Debug)]
591pub enum Solved {
592    /// The declaration's typed term, with the final substitution applied to every node
593    /// — the *zonk*. Its own `tpe` is the declaration's type; each node below it
594    /// carries the type inference solved for that sub-expression.
595    Typed(TypedTerm),
596    /// A declaration of a `module foreign` facade, whose body is a synthetic
597    /// placeholder rather than anything the user wrote. Nothing about it is inferred.
598    ///
599    /// This variant carries nothing, so [`Solved::typed`] answers `None` for it: the
600    /// declaration's type is the signature the facade declares, and it stays where
601    /// canonicalization put it, on `canonical::Value::TypedValue`'s `tpe`. A consumer
602    /// reading these entries is walking the same `canonical::Module` the map was
603    /// solved from — `type_check` takes one and keys the map the way its `values`
604    /// is keyed — so the signature is one lookup away, and repeating it here would be
605    /// a second copy of it rather than something inference established. [`build`] is
606    /// what reads it back out.
607    NoBody,
608    /// `value_to_term_and_annotation` could not translate the declaration into the
609    /// typer's term language — a `VarKernel` reference, a float pattern, or a pattern
610    /// nested inside a constructor or tuple pattern, whether a `case` branch or a
611    /// parameter wrote it. Nothing about the declaration was checked.
612    ///
613    /// Not an [`Error`](crate::compiler::typer::Error): it is a gap in the typer rather
614    /// than a mistake in the source. What it wants is a warning, which the compiler does not have yet (`ERR-8`, see
615    /// `docs/tickets/README.md`) — hence the span, so that the warning has a caret the
616    /// day it exists. *Which* of the constructs tripped it is not carried:
617    /// `value_to_term_and_annotation` answers `Option`, so the reason does not survive
618    /// the return.
619    Untranslatable {
620        /// Where the declaration was written, annotation and body together — the only
621        /// position available, since the construct that stopped the translation is not
622        /// reported back.
623        span: NodeSpan,
624    },
625    /// Inference reached a name the typer's environment does not hold, and nothing
626    /// about the declaration was checked.
627    ///
628    /// That environment holds a declared type for every value in reach that has one:
629    /// the values and constructors every imported interface exposes, and this module's
630    /// own constructors and annotated declarations. A declaration of this module
631    /// written without an annotation has no declared type, and a name reaching one
632    /// lands here. That is not a mistake in the source, which is why this is not an
633    /// [`Error`](crate::compiler::typer::Error) either. A name that genuinely does not
634    /// exist is caught earlier, by canonicalization, as
635    /// `canonical::Error::VariableNotFound`, with a caret under the name.
636    UnboundName {
637        /// The name as inference looked it up.
638        name: String,
639        /// Where it was written.
640        span: NodeSpan,
641    },
642}
643
644impl Solved {
645    /// The typed term, for a declaration that has one.
646    pub fn typed(&self) -> Option<&TypedTerm> {
647        match self {
648            Solved::Typed(term) => Some(term),
649            _ => None,
650        }
651    }
652}

654// ── Building a module ─────────────────────────────────────────────────────────
655
656/// Turn a checked module and what the typer solved for it into the IR a backend reads.
657///
658/// `solved` is consumed rather than borrowed: a [`Declaration`] owns its body, and the
659/// only other holder of these terms is the caller that just received them.
660///
661/// Every value of `module` ends up in exactly one of [`Module::declarations`] and
662/// [`Module::unchecked`] — see the second field for why nothing may merely go missing.
663pub fn build(module: &canonical::Module, solved: HashMap<Name, Solved>) -> Module {
664    let mut unions: Vec<Union> = module
665        .types
666        .iter()
667        .map(|(name, union)| Union {
668            name: module.name.qualify_name(name),
669            variables: union.variables.clone(),
670            variants: variants_of(union),
671        })
672        .collect();
673    unions.sort_by(|left, right| {
674        left.name
675            .to_name()
676            .as_str()
677            .cmp(right.name.to_name().as_str())
678    });
679
680    // Type variables in a facade signature are numbered from here. Each signature is
681    // translated on its own and is never unified with anything, so the numbering only
682    // has to be consistent within one declaration.
683    let mut counter = 0u32;
684
685    let mut solved = solved;
686    let mut names: Vec<&Name> = module.values.keys().collect();
687    names.sort_by(|left, right| left.as_str().cmp(right.as_str()));
688
689    let mut declarations = Vec::new();
690    let mut unchecked = Vec::new();
691
692    for name in names {
693        let value = &module.values[name];
694        let span = value.span();
695
696        match solved.remove(name) {
697            Some(Solved::Typed(term)) => {
698                let tpe = term.tpe.clone();
699                let (parameters, expression) = peel(term, value.arity());
700
701                declarations.push(Declaration {
702                    name: name.clone(),
703                    arity: parameters.len(),
704                    tpe,
705                    body: Some(Body {
706                        parameters,
707                        expression,
708                    }),
709                    span,
710                });
711            }
712            // A facade signature: the type is the one canonicalization recorded, and
713            // the arity is what the companion's parameter list has to be.
714            Some(Solved::NoBody) => match facade_signature(value, &mut counter) {
715                Some((arity, tpe)) => declarations.push(Declaration {
716                    name: name.clone(),
717                    arity,
718                    tpe,
719                    body: None,
720                    span,
721                }),
722                None => unchecked.push(Unchecked {
723                    name: name.clone(),
724                    span,
725                }),
726            },
727            // Untranslatable, UnboundName, and — impossible today, since `type_check`
728            // answers for every value it was given — a declaration with no entry at all.
729            _ => unchecked.push(Unchecked {
730                name: name.clone(),
731                span,
732            }),
733        }
734    }
735
736    let initialisation_order = canonical::initialisation_order(module);
737
738    Module {
739        name: module.name.clone(),
740        foreign: module.binding_foreign,
741        unions,
742        declarations,
743        unchecked,
744        initialisation_order,
745    }
746}

748/// A union's constructors, each with the position and the argument count both targets
749/// need.
750pub(crate) fn variants_of(union: &canonical::UnionType) -> Vec<Variant> {
751    union
752        .variants
753        .iter()
754        .enumerate()
755        .map(|(index, ctor)| Variant {
756            name: ctor.name.clone(),
757            index,
758            arity: ctor.type_parameters.len(),
759        })
760        .collect()
761}
762
763/// Split `arity` parameters off the front of a typed term.
764///
765/// `value_to_term_and_annotation` wraps a declaration's body in one `Fun` per parameter,
766/// so the first `arity` nodes of the spine are exactly those parameters and nothing else
767/// builds a `Fun` — the language has no lambda. Stopping early on anything that is not a
768/// `Fun` keeps a term that somehow disagreed with its declaration from being read past
769/// its end; the parameters handed back are the ones that were really there, which is why
770/// [`Declaration::arity`] is their count.
771fn peel(term: TypedTerm, arity: usize) -> (Vec<TypeBinder>, TypedTerm) {
772    let mut parameters = Vec::with_capacity(arity);
773    let mut term = term;
774
775    while parameters.len() < arity {
776        let TypedTerm { span, tpe, kind } = term;
777
778        match kind {
779            TypedTermKind::Fun { param, body } => {
780                parameters.push(param);
781                term = *body;
782            }
783            kind => {
784                term = TypedTerm { span, tpe, kind };
785                break;
786            }
787        }
788    }
789
790    (parameters, term)
791}

793/// The arity and the type of a facade's signature, when it has one to read.
794///
795/// A facade declaration has no parameters to count — it is a signature and a synthetic
796/// body — so its arity is the number of arrows in the type it declares: the companion's
797/// export takes a parameter list of that length, and no arrow at all is [a facade
798/// constant](../../../docs/spec/interop.md#facade-constants).
799///
800/// `None` is a facade declaration carrying no annotation, which nothing produces today —
801/// a facade's declarations are signatures — and which would have no type to emit against.
802fn facade_signature(value: &canonical::Value, counter: &mut u32) -> Option<(usize, Type)> {
803    match value {
804        canonical::Value::Value { .. } => None,
805        canonical::Value::TypedValue { tpe, .. } => {
806            let mut variables = HashMap::new();
807            let translated =
808                crate::compiler::typer::canonical_type_to_typer_type(tpe, &mut variables, counter)?;
809
810            Some((signature_arity(tpe), translated))
811        }
812    }
813}
814
815/// How many arguments a value of this type takes: the length of its arrow spine.
816fn signature_arity(tpe: &canonical::Type) -> usize {
817    match tpe {
818        canonical::Type::Arrow(_, result) => 1 + signature_arity(result),
819        _ => 0,
820    }
