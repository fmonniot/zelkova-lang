1//! The Zelkova compiler
2//!
3//!
4//!# How to compile a package ?
5//!
6//! Note: an interface is built for every module that checks and kept for whatever
7//! imports it, within this package and in the packages that depend on it. What is
8//! still missing is emitting one, so a dependency is compiled from source on every
9//! build.
10//!
11//! 1. Read the package's `zelkova.toml` manifest, and resolve the build: every package
12//!    reachable through `dependencies`, plus the root package's `test-dependencies`, each
13//!    ordered after the packages it depends on. Steps 2 to 6 then run once per package —
14//!    bar the ones only `test-dependencies` reaches, which a build that did not ask for
15//!    the tests resolves and leaves uncompiled — over the two source roots: `src/` and,
16//!    for the root package when its tests were
17//!    asked for, `tests/`, beside its own manifest. Before a package's modules are
18//!    checked, the whole map of module names it can import is built — its own, plus each
19//!    direct dependency's public modules under that package's namespace or, unwrapped,
20//!    under their own names — and a name two modules both answer to stops that package
21//!    there.
22//! 2. Collect all `*.zelkova` files with their path name relatives to the root.
23//! 3. Create a `SourceFiles` mapping from `ModuleName` to `parser::Module`.
24//!     1. module names are deduced from file name
25//!     2. parsing is done through `parser::parse`
26//!     3. Verify that `parser::Module.name` match the one from the file system
27//! 4. Build a dependency graphs from the modules import
28//!     1. build it
29//!     2. Verify there is no cyclic relation between modules
30//! 5. Following the deps graph,
31//!     1. canonicalize each modules
32//!     1. check each module (type check, exhaustiveness, etc…), and build the `ir::Module`
33//!        a backend reads out of the canonical module and what the typer solved
34//!     1. Bonus point to parallelize the tree branches which are not dependent on each others
35//! 6. Once we have a module with all checks passing, create its interface and emit AST/interface
36//! 7. Report. Each phase returns every error it found, `check_module` tags those with
37//!    the module they came from, and `compile_package` accumulates them across modules
38//!    and renders them all through `CompilationError::as_diagnostic` — the one place a
39//!    `Diagnostic` is built. See the `PhaseError` trait for what a phase error owes it.
40//!

102/// A package name: one flat identifier, ASCII lowercase letters, digits and hyphens,
103/// starting with a letter, with every hyphen followed by a letter —
104/// [`docs/spec/packages.md`](../../docs/spec/packages.md#the-manifest)'s whole rule for
105/// `name`. That shape is what keeps a package name and a module name from ever being
106/// confused (one is lowercase-with-hyphens, the other uppercase-with-dots), and what makes
107/// the namespace a package's name derives unambiguous.
108///
109/// The only way to build one is [`PackageName::new`], which rejects anything that does not
110/// match the rule — there is no way to hold a `PackageName` that manifest validation would
111/// have refused.
112#[derive(Eq, PartialEq, Hash, Debug, Clone)]
113pub struct PackageName(String);
114
115/// `PackageName::new` refused this string; it names the input so a caller can report it.
116#[derive(Debug, Clone, PartialEq, Eq)]
117pub struct InvalidPackageName(pub String);
118
119impl PackageName {
120    /// Build a `PackageName`, or say why `name` is not one.
121    pub fn new<S: Into<String>>(name: S) -> Result<PackageName, InvalidPackageName> {
122        let name = name.into();
123        if is_legal_package_name(&name) {
124            Ok(PackageName(name))
125        } else {
126            Err(InvalidPackageName(name))
127        }
128    }
129
130    pub fn as_str(&self) -> &str {
131        &self.0
132    }
133
134    /// The prefix this package's modules are named through from outside it: the name
135    /// split at its hyphens, each piece capitalised, joined —
136    /// [*The namespace*](../../docs/spec/packages.md#the-namespace). `acme-widgets` is
137    /// `AcmeWidgets`, `todo` is `Todo`.
138    ///
139    /// It is a [`Name`] and not a [`PackageName`]: what comes back is a module-name
140    /// prefix, and the whole point of the shape rule above is that the two are never
141    /// confusable. Distinct package names give distinct namespaces, which is what lets
142    /// two wrapped dependencies keep out of each other's way with nothing checked.
143    ///
144    /// A package never writes its own namespace, so nothing inside the package being
145    /// compiled goes through here: [`resolve::visible_modules`] is the one caller, and
146    /// it applies this only to a *dependency*'s modules.
147    pub fn namespace(&self) -> Name {
148        let mut namespace = String::with_capacity(self.0.len());
149
150        for piece in self.0.split('-') {
151            let mut characters = piece.chars();
152            if let Some(first) = characters.next() {
153                namespace.extend(first.to_uppercase());
154                namespace.push_str(characters.as_str());
155            }
156        }
157
158        Name::new(namespace)
159    }
160}

162impl std::fmt::Display for PackageName {
163    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
164        write!(f, "{}", self.0)
165    }
166}

168/// ASCII lowercase letters, digits and hyphens; starts with a letter; every hyphen is
169/// immediately followed by a letter (so no leading, trailing or doubled hyphen, and no
170/// hyphen before a digit).
171fn is_legal_package_name(name: &str) -> bool {
172    match name.chars().next() {
173        Some(c) if c.is_ascii_lowercase() => {}
174        _ => return false,
175    }
176
177    for (i, c) in name.char_indices() {
178        if c == '-' {
179            match name[i + 1..].chars().next() {
180                Some(next) if next.is_ascii_lowercase() => {}
181                _ => return false,
182            }
183        } else if !(c.is_ascii_lowercase() || c.is_ascii_digit()) {
184            return false;
185        }
186    }
187
188    true
189}

232/// An interface is trim down version of a module.
233///
234/// We use it when translating a local source AST into its canonical form as
235/// an optimization technique. Instead of parsing every source files on each
236/// file compilation, we save the publicly exposed information of a successfully
237/// parsed module and only load this information on module depending on it.
238///
239/// All `Interface` indices are using non-qualified names. To get the qualified
240/// version, simply use `I.module_name.qualify_name(&name)`.
241// TODO Union types will need a way to reflect that some type constructor are private
242//
243// `Clone` because one interface reaches more than one place: a public module of a
244// dependency is inserted into the environment of every package that imports it, under
245// whichever spelling that package names it by (`resolve::visible_modules`). The
246// interface itself is the same either way — a spelling is the importer's, and what an
247// `Interface` carries is the module's own name.
248#[derive(Debug, Clone)]
249pub struct Interface {
250    pub module_name: ModuleName,
251    /// Each value's type, paired with where its declaration (annotation and body
252    /// together) was written — [`canonical::Value::span`] — so a diagnostic about a
253    /// name found here can point at the declaration, not just name it.
254    pub values: HashMap<Name, (NodeSpan, canonical::Type)>,
255    pub unions: HashMap<Name, canonical::UnionType>,
256    // TODO type aliases
257    //aliases: HashMap<Name, >
258    /// infixes is a map from the operator symbol to its information
259    pub infixes: HashMap<Name, canonical::Infix>,
260    /// The type of an exposed infix's own backing function, keyed by that
261    /// function's unqualified name — populated only when the function is *not*
262    /// separately present in [`values`](Self::values), i.e. the header exposes
263    /// the operator but not the function by name (`infix left 6 (+) = add`,
264    /// header exposing `(+)` and not `add`, is `std/core`'s own shape for every
265    /// operator it declares).
266    ///
267    /// `canonical::environment::imported_infix` is what needs it: an operator is
268    /// resolved through its `infix` declaration, and the declaration alone names
269    /// the backing function without saying anything about its type. Whichever of
270    /// the two maps holds it, that is where the type comes from — and for an
271    /// operator whose function is not separately exposed, this is the only one
272    /// that can.
273    ///
274    /// Nothing else reads it, and in particular nothing inserts it into an
275    /// importing module's scope under its own name: a function that backs an
276    /// exposed operator is importable by name only when the header says so too
277    /// (`BUG-9`), and then it is [`values`](Self::values) that carries it.
278    pub infix_functions: HashMap<Name, (NodeSpan, canonical::Type)>,
279    /// The file this interface's module was read from, when the caller knows it.
280    ///
281    /// It is what makes a diagnostic about an imported name able to underline that
282    /// name's *own* source rather than merely naming its module. Nothing inside a
283    /// module check can supply it: a phase only ever sees one module and never
284    /// learns its [`SourceFileId`] (see [`PhaseError`]). Driver code does, so
285    /// [`canonical::Module::to_interface`] takes it as an argument, and its one
286    /// caller — [`dependencies::ModuleWalker::check_in_order`], which like
287    /// [`compile_package`] is a driver loop and already holds the file each module
288    /// came from — passes it there. A hand-built interface, as every test below
289    /// `check_module` constructs, passes `None`; [`Interface::source_span`] then has
290    /// no file to pair a span with and returns `None`, so the diagnostic degrades to
291    /// no secondary label rather than a wrong one.
292    pub file: Option<SourceFileId>,
293}

295impl Interface {
296    /// Pair a [`NodeSpan`] taken from this interface's own data — a value's
297    /// declaration, a [`canonical::UnionType`]'s or [`canonical::Infix`]'s `span`
298    /// field — with the file it was written in, when both halves are known.
299    ///
300    /// Both halves are needed: a `NodeSpan` with nothing behind it (a hand-built
301    /// test value) or an interface with no attached file (same) leaves nothing
302    /// honest to build, and `None` is that answer — the caller renders no label
303    /// rather than one pointing at byte 0 of the wrong file.
304    pub fn source_span(&self, span: NodeSpan) -> Option<SourceSpan> {
305        match (self.file, span.span()) {
306            (Some(file), Some(span)) => Some(SourceSpan { file, span }),
307            _ => None,
308        }
309    }
310}

312/// One underlined region of the user's source, and what to say about it.
313///
314/// # `file`: when a label is not about the module under check
315///
316/// A [`codespan_reporting::Label`] needs a file id as well as a byte range. Most
317/// labels don't carry one themselves: a phase only ever sees one module, so its
318/// spans belong to the file that module was read from, and [`compile_package`] —
319/// the only place that knows which file that is — supplies it for the whole
320/// diagnostic at render time. `file: None` is that case, and it covers everything
321/// built before `ERR-5`.
322///
323/// `Some` is the escape hatch: a label built from a [`SourceSpan`] cloned out of an
324/// [`Interface`] (via [`Interface::source_span`]) already carries its own file,
325/// generally a *different* one from the module being checked — "the annotation you
326/// are contradicting is over there, in `Basics`" — and that id is used verbatim
327/// instead of the diagnostic's.
328///
329/// `primary` is the rustc distinction, and it applies independently of `file`: the
330/// caret under the thing that is wrong is primary even when it is local, and
331/// "defined here" in another file is secondary even though it is the only label
332/// pointing into that file.
333#[derive(Debug, Clone, PartialEq)]
334pub struct SpanLabel {
335    pub span: Span<BytePos>,
336    pub message: String,
337    pub primary: bool,
338    pub file: Option<SourceFileId>,
339}

341/// What a compiler phase owes the diagnostic reporter.
342///
343/// Each phase keeps its own error type — one enum for the whole compiler would make
344/// every phase depend on the vocabulary of every other. What they have to share is
345/// the ability to describe themselves in the user's terms, because
346/// [`CompilationError::as_diagnostic`] is the only place a `Diagnostic` is ever
347/// built and it has no phase-specific knowledge to fall back on. Dumping
348/// `format!("{:?}", e)` into a note is exactly what this trait replaces: a `Debug`
349/// dump names Rust types, not source constructs.
350///
351/// # How much a span can say, and where that stops
352///
353/// Every production in `grammar.lalrpop` that builds a node captures `@L`/`@R`, so
354/// declarations, expressions, patterns and types all know where they were written,
355/// and canonicalization copies that onto the node it builds. An error raised from one
356/// of those construction sites returns a [`SpanLabel`] from
357/// [`labels`](PhaseError::labels) and gets a caret under the text it is about — an
358/// unresolvable name is underlined at the identifier, not across the declaration
359/// containing it.
360///
361/// Not every error can. `labels` defaults to empty and that is a real answer, not a
362/// stub: an error raised while walking a node the grammar does not span — an
363/// `exposing` list, say — has nowhere to point, and renders as message-plus-notes
364/// with no caret, exactly as every phase after parsing used to. An error that groups
365/// others (`canonical::Error::Many`, `EnvironmentErrors`) has no position of its own
366/// and flattens its members' labels instead, the way it already flattens their
367/// messages.
368///
369/// The typer is the phase that has to work for this, and it does: it does not check
370/// the canonical AST but a term language of its own, so it carries each canonical
371/// node's span into that language, each constraint records the term and the *reason*
372/// it came from, and `unify` reports the origin of the constraint it failed on. A
373/// type error therefore underlines the sub-expression that disagrees and adds a
374/// secondary label under the annotation that says what was expected (`ERR-4`).
375///
376/// `parser::Error` is still the one phase error that does not go through this trait
377/// at all — it builds its own labelled `Diagnostic` through `parser::Error::diagnostic`.
378///
379/// # The two ways a label learns its `SourceFileId`
380///
381/// A phase still never knows the id of the file the module it is checking came
382/// from — that half is unchanged, and stays attached by `compile_package`, the only
383/// place that knows it, the way `CompilationError::Source` already works. A
384/// [`SpanLabel`] with `file: None` — everything built before `ERR-5` — means
385/// exactly that: "in the module under check", resolved at render time.
386///
387/// That is right for an error entirely about one module and cannot cover a
388/// diagnostic that also names something written elsewhere — "the annotation you
389/// are contradicting is over there, in `Basics`". For that, `file` carries its own
390/// [`SourceFileId`] instead, taken from a [`SourceSpan`] cloned out of an
391/// [`Interface`] via [`Interface::source_span`]. An `Interface` can offer that
392/// because it is not a phase: it is built by driver code
393/// (`dependencies::ModuleWalker::check_in_order`) that already has the file the
394/// module it just checked came from, and stamps it onto the `Interface` before
395/// handing it to whoever imports next. `canonical::Type` still carries no span of
396/// its own — seeing why is worth a look at that type's own documentation.
397pub trait PhaseError {
398    /// One line naming what went wrong, in the vocabulary of the user's source.
399    ///
400    /// This is rendered as the diagnostic's headline, so it has to read on its own:
401    /// no `{:?}`, no Rust type names.
402    fn message(&self) -> String;
403
404    /// Supporting detail, one string per rendered note. Empty by default.
405    fn notes(&self) -> Vec<String> {
406        Vec::new()
407    }
408
409    /// The regions of the user's source this error is about, if it knows any.
410    ///
411    /// Empty — the default — means this error has no position to point at, and it
412    /// renders as message-plus-notes with no caret. See the trait's documentation.
413    fn labels(&self) -> Vec<SpanLabel> {
414        Vec::new()
415    }
416
417    /// This error's message followed by its notes.
418    ///
419    /// A `Diagnostic` has one headline, so an error that ends up inside a group —
420    /// several errors from one phase, or a variant like `canonical::Error::Many`
421    /// that wraps others — has to give up its headline and become notes. This is
422    /// that demotion, in one place, so a group cannot silently drop the message of
423    /// a member it swallowed.
424    fn message_and_notes(&self) -> Vec<String> {
425        std::iter::once(self.message())
426            .chain(self.notes())
427            .collect()
428    }
429}

431/// Turn `SpanLabel`s into the `codespan_reporting::Label`s a `Diagnostic` renders.
432///
433/// `fallback` is the file a label with none of its own resolves to — the module
434/// currently being checked, when the caller has one. So `fallback` is a fallback
435/// rather than a gate: a label needs *some* file, because a byte range on its own
436/// does not say which file to underline, but a [`SpanLabel`] carrying its own
437/// [`SpanLabel::file`] already has one and renders whether or not `fallback` is
438/// `Some`. Only a label with neither is a byte range nobody can place, and that one
439/// is dropped rather than guessed at.
440///
441/// This is the one place that distinction is applied; both [`phase_diagnostic`] (a
442/// fallback file, from the module under check) and the dependency-cycle arm of
443/// `CompilationError::as_diagnostic_in` (no fallback — a cycle has no single
444/// module) go through it.
445fn spans_to_labels(
446    labels: Vec<SpanLabel>,
447    fallback: Option<SourceFileId>,
448) -> Vec<Label<SourceFileId>> {
449    labels
450        .into_iter()
451        .filter_map(|l| {
452            // A label with its own file — a `SourceSpan` cloned out of an
453            // `Interface`, or (`ERR-6`) a `CycleEdge`'s file — points into that
454            // file instead of falling back. That is the whole mechanism `ERR-5`
455            // adds: everything built before it left `file` `None` and relied on
456            // `fallback` here.
457            let label_file = l.file.or(fallback)?;
458            let range = l.span.to_range();
459            let label = if l.primary {
460                Label::primary(label_file, range)
461            } else {
462                Label::secondary(label_file, range)
463            };
464            Some(label.with_message(l.message))
465        })
466        .collect()
467}

469/// Render the errors one phase produced for one module.
470///
471/// A `Diagnostic` has room for exactly one headline, so a lone error gets to be that
472/// headline and a group is summarised instead, with every message demoted to a note.
473/// `phase` names the phase in that summary line ("canonical", "type", …).
474///
475/// `file` is the module's source file when the caller knows it, and it is handed
476/// straight to [`spans_to_labels`] as the fallback that document describes: a label
477/// of its own — the cross-module ones `ERR-5` added — renders regardless, so a
478/// `CompilationError` built by hand, as the tests in this module do, loses only the
479/// labels about the module under check. `compile_package` always wraps in
480/// [`CompilationError::InFile`] and so loses none.
481///
482/// Both branches attach labels: only the headline demotion differs between one error
483/// and a group, and an error that got swallowed into a note still knows where it was.
484fn phase_diagnostic<E: PhaseError>(
485    module: &Name,
486    phase: &str,
487    errors: &[E],
488    file: Option<SourceFileId>,
489) -> Diagnostic<SourceFileId> {
490    let labels =
491        |errors: &[E]| spans_to_labels(errors.iter().flat_map(|e| e.labels()).collect(), file);
492
493    match errors {
494        [only] => Diagnostic::error()
495            .with_message(format!("[{}] {}", module, only.message()))
496            .with_labels(labels(errors))
497            .with_notes(only.notes()),
498        many => Diagnostic::error()
499            .with_message(format!(
500                "[{}] {} {} error{}",
501                module,
502                many.len(),
503                phase,
504                if many.len() == 1 { "" } else { "s" }
505            ))
506            .with_labels(labels(many))
507            .with_notes(many.iter().flat_map(|e| e.message_and_notes()).collect()),
508    }
509}

511/// Every way compiling a package can fail, tagged with the phase that failed.
512///
513/// Each phase-carrying variant holds *all* the errors that phase produced for one
514/// module rather than only the first, plus the module's [`Name`], which is what
515/// `as_diagnostic` puts in front of the message. Rendering goes through
516/// [`PhaseError`]; see that trait for why no variant here carries a span.
517#[derive(Debug)]
518pub enum CompilationError {
519    /// The package's `zelkova.toml` is missing, malformed, or fails one of its own
520    /// field-level rules (an illegal `name`, a dependency entry naming no source, …).
521    ///
522    /// Raised before [`LoadingFiles`](CompilationError::LoadingFiles) even runs — a
523    /// package's source root is derived from its manifest, so there is nothing to walk
524    /// until the manifest is known good — with one exception:
525    /// [`PrivateModuleNotFound`](manifest::ManifestError::PrivateModuleNotFound) needs the
526    /// package's parsed modules and is pushed after them.
527    ///
528    /// It carries no [`SourceFileId`] either way. A manifest error's location is a byte
529    /// range in `zelkova.toml`, and that file is never read into the database, so each
530    /// error names its manifest in its own message instead.
531    Manifest(Vec<manifest::ManifestError>),
532    /// The build could not be resolved: a dependency that could not be obtained or
533    /// read, a circular package graph, or two modules answering to one name in one
534    /// package.
535    ///
536    /// Like [`Manifest`](CompilationError::Manifest) it carries no
537    /// [`SourceFileId`]: what each of these errors is about is a `zelkova.toml`, which
538    /// is not a file the database holds, so each names its manifest in its own message.
539    /// The graph half is raised before any source is loaded and goes back to the caller
540    /// unrendered; the name-collision half is pushed onto `compile_package`'s
541    /// accumulator once the packages' modules are known, and stops that package being
542    /// compiled.
543    Resolution(Vec<resolve::Error>),
544    LoadingFiles(Vec<SourceFileError>),
545    Source(parser::Error, SourceFileId),
546    Canonical(Vec<canonical::Error>, Name),
547    /// Type checking failed for the named module.
548    Type(Vec<typer::Error>, Name),
549    /// Exhaustiveness checking failed for the named module. Unreachable while
550    /// `exhaustiveness::check` is a stub, but rendered like any other phase.
551    Exhaustiveness(Vec<exhaustiveness::Error>, Name),
552    DependenciesError(dependencies::Error),
553
554    /// An error together with the file the module it belongs to was read from.
555    ///
556    /// A phase never knows its [`SourceFileId`], so the labels its errors produce are
557    /// byte ranges with no file attached. This is where the two halves are put
558    /// together, and it has exactly one constructor: [`compile_package`], which is
559    /// the only place that knows which file a module was parsed from. Nothing else
560    /// should build it — an id guessed anywhere else would underline the wrong file.
561    InFile(Box<CompilationError>, SourceFileId),
562
563    /// Every error accumulated over one compilation pass.
564    ///
565    /// `compile_package` does not stop on the first failure: it keeps going so that
566    /// one broken module cannot hide the diagnostics of the others. This variant is
567    /// how that accumulation becomes a failure again at the end of the pass, with the
568    /// typed errors still intact for the caller to inspect.
569    Many(Vec<CompilationError>),
570}
571
572impl CompilationError {
573    /// Turn this error into the diagnostic the user reads.
574    ///
575    /// This is the compiler's single rendering point — `compile_package` calls it
576    /// and nothing else builds a `Diagnostic` from a phase error. It is public so
577    /// that a test can assert on what the user is actually shown, rather than on
578    /// `is_err()`: what a failure *says* is the behaviour this method exists for.
579    pub fn as_diagnostic(&self) -> Diagnostic<SourceFileId> {
580        self.as_diagnostic_in(None)
581    }
582
583    /// The name of the module this error belongs to, when it has one.
584    ///
585    /// `compile_package` uses it to look up the file the module was read from, which
586    /// is how an [`InFile`](CompilationError::InFile) wrapper gets its id.
587    pub fn module(&self) -> Option<&Name> {
588        match self {
589            CompilationError::Canonical(_, module)
590            | CompilationError::Type(_, module)
591            | CompilationError::Exhaustiveness(_, module) => Some(module),
592            CompilationError::InFile(inner, _) => inner.module(),
593            _ => None,
594        }
595    }
596
597    /// `as_diagnostic`, carrying the file the error's module was read from.
598    ///
599    /// `file` is `None` until an [`InFile`](CompilationError::InFile) wrapper supplies
600    /// one, which only `compile_package` builds. Everything downstream of that
601    /// distinction is in `phase_diagnostic`, where it serves as the fallback file for
602    /// labels that do not name one themselves.
603    fn as_diagnostic_in(&self, file: Option<SourceFileId>) -> Diagnostic<SourceFileId> {
604        match self {
605            // The one arm that changes `file`, and the only one that can: it is the
606            // only variant that carries an id.
607            CompilationError::InFile(inner, id) => inner.as_diagnostic_in(Some(*id)),
608            // The one phase that carries spans renders its own labelled diagnostic.
609            CompilationError::Source(err, file_id) => err.diagnostic(*file_id),
610            // Only `PrivateModuleNotFound` ever reaches this arm: every other
611            // `ManifestError` is raised before the file database exists and goes back to
612            // the caller unrendered. That one is pushed after parsing, so a database does
613            // exist here — but the location this error wants is a byte range in
614            // `zelkova.toml`, which is not a file that database holds, so it renders with
615            // no label and each error names itself and its manifest in a note.
616            CompilationError::Manifest(errors) => Diagnostic::error()
617                .with_message("Error in the package manifest")
618                .with_notes(errors.iter().flat_map(|e| e.message_and_notes()).collect()),
619            // A resolution error is about a manifest, the same as the arm above, and
620            // renders the same way: no label, because `zelkova.toml` is not in the file
621            // database. A lone error keeps its own headline — the collision message
622            // names both the module and the package, and burying it under a summary
623            // line would cost the user the one sentence that says what to change.
624            CompilationError::Resolution(errors) => match errors.as_slice() {
625                [only] => Diagnostic::error()
626                    .with_message(only.message())
627                    .with_notes(only.notes()),
628                many => Diagnostic::error()
629                    .with_message(format!(
630                        "{} error{} while resolving the build",
631                        many.len(),
632                        if many.len() == 1 { "" } else { "s" }
633                    ))
634                    .with_notes(many.iter().flat_map(|e| e.message_and_notes()).collect()),
635            },
636            // Loading failures are not attached to a module — there is no module yet,
637            // and each error names its own file instead.
638            CompilationError::LoadingFiles(errors) => Diagnostic::error()
639                .with_message("Error while loading the package files")
640                .with_notes(errors.iter().flat_map(|e| e.message_and_notes()).collect()),
641            CompilationError::Canonical(errors, module) => {
642                phase_diagnostic(module, "canonical", errors, file)
643            }
644            CompilationError::Type(errors, module) => {
645                phase_diagnostic(module, "type", errors, file)
646            }
647            CompilationError::Exhaustiveness(errors, module) => {
648                phase_diagnostic(module, "exhaustiveness", errors, file)
649            }
650            // A dependency cycle belongs to the package, not to any one module, so it
651            // does not go through `phase_diagnostic` — there is no module to supply
652            // the fallback file that helper takes. Its labels don't need one: each
653            // `CycleEdge` (`ERR-6`) carries the file the `import` forming it was
654            // written in, so `spans_to_labels` is called with `None` and a label
655            // with no file of its own (an edge `ModuleWalker::new` couldn't map back
656            // to a file) is dropped rather than guessed at.
657            CompilationError::DependenciesError(err) => Diagnostic::error()
658                .with_message(err.message())
659                .with_labels(spans_to_labels(err.labels(), None))
660                .with_notes(err.notes()),
661            // `compile_package` renders each accumulated error individually rather than
662            // wrapping first, so this arm only fires when a `Many` is rendered as a
663            // whole. It summarises rather than repeating what those diagnostics said.
664            //
665            // This is the one group that deliberately does not flatten its members'
666            // labels. The phase-error groups that do — `canonical::Error::Many`,
667            // `EnvironmentErrors` — hold errors from a single module, so their labels
668            // all belong to one file and the group is the *only* thing rendered. This
669            // one spans the whole package: its members are `InFile` wrappers naming
670            // different files, and each has already been rendered with its own carets
671            // by the time this summary is built. Flattening here would draw every
672            // caret in the package a second time under one headline.
673            CompilationError::Many(errors) => Diagnostic::error()
674                .with_message(format!(
675                    "compilation failed with {} error{}",
676                    errors.len(),
677                    if errors.len() == 1 { "" } else { "s" }
678                ))
679                .with_notes(
680                    errors
681                        .iter()
682                        .map(|e| e.as_diagnostic_in(file).message)
683                        .collect(),
684                ),
685        }
686    }
687
688    fn from(err: parser::Error, source_id: SourceFileId) -> Self {
689        CompilationError::Source(err, source_id)
690    }
691}

725/// Which of the root package's source roots a build compiles.
726///
727/// A package has two, `src/` and `tests/`, and only the first is ever compiled for a
728/// package that is being depended on: a dependency's `tests/` is not read, not resolved
729/// and not observable ([*Tests*](../../docs/spec/packages.md#tests)). So this is a
730/// property of the build rather than of a package, and it applies to the package the
731/// compiler was pointed at.
732#[derive(Debug, Clone, Copy, PartialEq, Eq)]
733enum TestRoot {
734    /// `src/` alone.
735    Skipped,
736    /// Both roots. The modules under `tests/` are checked against the package's own
737    /// modules — the private ones included — and the public modules of both dependency
738    /// maps.
739    Compiled,
740}
741
742/// Compile the package rooted at `package_dir` — a directory holding a `zelkova.toml`
743/// manifest beside a `src/` source root, per
744/// [`docs/spec/packages.md`](../../docs/spec/packages.md#what-a-package-is) — and every
745/// package it depends on.
746///
747/// Its `tests/` root is not compiled; [`compile_package_with_tests`] is that build. A
748/// package is compiled from source the same way whether it is the one asked for or a
749/// dependency of it, and the whole build shares one file database and one error
750/// accumulator: an error in any package of it makes this return `Err`.
751pub fn compile_package(package_dir: &Path) -> Result<(), CompilationError> {
752    compile(package_dir, TestRoot::Skipped)
753}
754
755/// [`compile_package`], compiling the package's `tests/` root as well as its `src/`.
756///
757/// This is what running a package's own tests needs, and the only thing that ever reads
758/// a `tests/` root: the tests of the build's other packages are not compiled, because
759/// nothing outside a package reads its tests
760/// ([*Running a package's tests*](../../docs/spec/toolchain.md#running-a-packages-tests)).
761/// A package holding no `tests/` at all compiles exactly as it does through
762/// [`compile_package`].
763///
764/// It compiles the tests and does not run them: what makes a declaration a test is
765/// [its type](../../docs/spec/packages.md#what-a-test-is), and there is no runner.
766pub fn compile_package_with_tests(package_dir: &Path) -> Result<(), CompilationError> {
767    compile(package_dir, TestRoot::Compiled)
768}

770fn compile(package_dir: &Path, tests: TestRoot) -> Result<(), CompilationError> {
771    // Error reporter
772    let mut writer = StandardStream::stderr(ColorChoice::Auto);
773    let config = codespan_reporting::term::Config {
774        tab_width: 2,
775        ..codespan_reporting::term::Config::default()
776    };
777
778    // Reports the outcome of one phase on stderr. Failing to write a status line is
779    // not itself a compilation failure, so the write results are deliberately
780    // discarded rather than unwrapped.
781    let mut print_status = |success: bool, text: String| {
782        let (color, label) = if success {
783            (Color::Green, "success")
784        } else {
785            (Color::Red, "failure")
786        };
787        let _ = writer.set_color(ColorSpec::new().set_bold(true).set_fg(Some(color)));
788        let _ = write!(&mut writer, "{}", label);
789        let _ = writer.reset();
790        let _ = writeln!(&mut writer, " {}", text);
791    };
792
793    // Step 1: read and validate the root package's manifest. This is the one failure
794    // that cannot be deferred to the usual accumulate-and-render path, because it
795    // happens before that path exists: the source root itself is derived from the
796    // manifest, so there is no build to walk, no accumulator and no file database yet.
797    // It goes back to the caller unrendered. Every failure after the accumulator below
798    // is created goes onto it instead, this package's source loading included.
799    debug!("phase: read package manifest");
800    let manifest = manifest::load(package_dir)?;
801    // The package the compiler was pointed at, which is the one whose `tests/` root
802    // this build compiles — every other package in the build is here because something
803    // depends on it, and a dependency's tests are never compiled.
804    let root_package = manifest.name.clone();
805
806    // Step 1b: resolve the build. Every package reachable from this one's two dependency
807    // maps, each ordered after the packages it depends on, so an
808    // `Interface` a package needs always exists by the time that package is
809    // compiled. The union is resolved whether or not the tests are being compiled, so
810    // that one version of each package and an acyclic graph are settled once for the
811    // build. A dependency's own manifest is read here, so this is raised before any
812    // source is loaded and goes back unrendered for the same reason the manifest above
813    // does.
814    debug!("phase: resolve the build");
815    let build = resolve::resolve(package_dir, manifest)?;
816
817    // Resolved is not compiled. A package reached only through `test-dependencies` is in
818    // the build so that the version and cycle rules can be settled over the union, and a
819    // build that did not ask for the tests has no use for anything it holds: no module
820    // here can import one, since a `test-dependency`'s modules are held out of the
821    // environment `src/` is checked against. Compiling it anyway would parse and check a
822    // package the user never reached for, print its status lines, and fail this build on
823    // an error inside it.
824    let test_only = match tests {
825        TestRoot::Compiled => std::collections::HashSet::new(),
826        TestRoot::Skipped => resolve::test_only_packages(&build, &root_package),
827    };
828
829    // Further steps will produce errors. We aggregate them here and report them at the
830    // end of the compilation phase, rather than stopping on the first one, so that a
831    // single broken module doesn't hide the diagnostics of every other module.
832    //
833    // They are kept as typed `CompilationError`s and not as already-rendered
834    // `Diagnostic`s for two reasons: `as_diagnostic` stays the single rendering point,
835    // and the accumulation is still meaningful as a return value — an empty vector is
836    // what makes this function return `Ok`.
837    let mut errors: Vec<CompilationError> = vec![];
838
839    // One file database for the whole build, so that a diagnostic about any module of
840    // any package renders against the file it was written in. `SourceFileId` is an
841    // index into this one database, and it travels inside `Interface`s that outlive
842    // the package they came from (`ERR-5`), which is exactly why there is one
843    // database and not one per package.
844    let mut sources = SourceFiles::new();
845
846    // What each compiled package offers its dependents: its public modules'
847    // `Interface`s, keyed by the module's name *within* that package. The spelling a
848    // depending package reaches one by — `AcmeWidgets.Size`, or `Size` when it
849    // unwraps — belongs to that package alone and is applied by `compile_in_build`.
850    let mut published: HashMap<PackageName, HashMap<Name, Interface>> = HashMap::new();
851
852    for package in &build {
853        if test_only.contains(&package.name) {
854            debug!(
855                "phase: skip package {} — reached through `test-dependencies` alone",
856                package.name
857            );
858            continue;
859        }
860
861        debug!("phase: compile package {}", package.name);
862
863        let tests = if package.name == root_package {
864            tests
865        } else {
866            TestRoot::Skipped
867        };
868
869        if let Some(public) = compile_in_build(
870            package,
871            &build,
872            &published,
873            tests,
874            &mut sources,
875            &mut errors,
876            &mut print_status,
877        ) {
878            published.insert(package.name.clone(), public);
879        }
880    }
881
882    // Step 6
883    // emit interfaces and generate code
884    debug!("phase: codegen");
885
886    // Step 7: report everything we accumulated, then let that accumulation decide the
887    // return value. Rendering the errors and returning `Ok` regardless was `BUG-1`.
888    for error in &errors {
889        // A rendering failure must not mask the compilation failure we are about to
890        // return, and there is nowhere left to report it to, so it is dropped.
891        let _ = term::emit_to_write_style(
892            &mut writer.lock(),
893            &config,
894            &sources,
895            &error.as_diagnostic(),
896        );
897    }
898
899    if errors.is_empty() {
900        Ok(())
901    } else {
902        Err(CompilationError::Many(errors))
903    }
904}

906/// Compile one package of a resolved build, and hand back what it offers its
907/// dependents.
908///
909/// `published` holds what every package compiled before this one offers — this
910/// package's dependencies among them, since [`resolve::resolve`] orders a package
911/// after everything it depends on. `sources` and `errors` are the build's, not this
912/// package's: every module of every package renders against one file database, and
913/// every error from any package makes the build fail.
914///
915/// `tests` says whether this package's `tests/` root is compiled beside its `src/`. It
916/// is [`TestRoot::Compiled`] for the package the compiler was pointed at, when the
917/// caller asked for tests, and for no other package in the build. The two roots are
918/// walked, parsed and checked separately, because they are two environments: a module
919/// under `tests/` sees the package's own modules, the private ones included, and the
920/// public modules of both dependency maps, while a module under `src/` sees neither a
921/// test module nor a `test-dependency`'s — an import naming one is a module that does
922/// not exist, the same as a private module of another package.
923///
924/// `None` means nothing here was compiled and this package publishes nothing. It
925/// always comes with at least one error already pushed onto `errors` — a dependency
926/// that did not compile, sources that could not be read, a name claimed twice, or a
927/// failure in one of this package's own modules — so a package that publishes nothing
928/// can never be read as one that compiled. A package whose modules failed publishes
929/// nothing for the same reason: its dependents would otherwise be checked against half
930/// an interface and report errors belonging to a module they never wrote.
931///
932/// There is deliberately no error return. Every way this can fail is a diagnostic about
933/// one package of a build whose other packages may already have accumulated diagnostics
934/// of their own, and a `Result` here is an invitation to `?` those out of
935/// [`compile_package`] past its reporting loop — which is the "nothing is rendered and
936/// then dropped" the accumulator exists to prevent.
937fn compile_in_build(
938    package: &resolve::ResolvedPackage,
939    build: &[resolve::ResolvedPackage],
940    published: &HashMap<PackageName, HashMap<Name, Interface>>,
941    tests: TestRoot,
942    sources: &mut SourceFiles,
943    errors: &mut Vec<CompilationError>,
944    print_status: &mut impl FnMut(bool, String),
945) -> Option<HashMap<Name, Interface>> {
946    let errors_before = errors.len();
947
948    // Step 1: what this package is compiled against. Only its *direct* dependencies:
949    // a package listed in a dependency's manifest and not in this one's is in the
950    // build and is not importable here
951    // (`docs/spec/packages.md#only-direct-dependencies-are-usable`).
952    //
953    // `test-dependencies` join them when this package's tests are compiled, and are
954    // resolved into the build whether or not they are
955    // (`docs/spec/packages.md#test-dependencies`). What keeps one out of `src/` is not
956    // that it is missing from the build but that its modules are held back from the
957    // environment `src/` is checked against, a few steps below.
958    //
959    // Sorted so that a build reports two broken entries in the same order every run.
960    let mut entries: Vec<(&PackageName, &manifest::Dependency)> =
961        package.manifest.dependencies.iter().collect();
962    if tests == TestRoot::Compiled {
963        entries.extend(package.manifest.test_dependencies.iter());
964    }
965    entries.sort_by(|left, right| left.0.as_str().cmp(right.0.as_str()));
966
967    let mut dependencies: Vec<resolve::DependencyModules<'_>> = Vec::new();
968    for (name, entry) in entries {
969        let resolved = build.iter().find(|candidate| &candidate.name == name);
970        let public = published.get(name);
971
972        match (resolved, public) {
973            (Some(resolved), Some(public)) => dependencies.push(resolve::DependencyModules {
974                package: resolved,
975                wrapped: entry.wrapped,
976                modules: public.keys().cloned().collect(),
977            }),
978            // The dependency is in the build — resolution succeeded, or we would not
979            // be here — and did not compile. Its own diagnostics say why; this one
980            // says which package was left uncompiled because of it, so a user reading
981            // a wall of errors from a dependency knows why nothing was said about the
982            // package they asked for.
983            //
984            // No status line goes with it. A status line reports a phase this package
985            // got through; a package abandoned before its first phase has none, and the
986            // diagnostic already says the same sentence in the same words.
987            _ => {
988                errors.push(CompilationError::Resolution(vec![
989                    resolve::Error::DependencyNotCompiled {
990                        package: package.name.clone(),
991                        dependency: name.clone(),
992                    },
993                ]));
994                return None;
995            }
996        }
997    }
998
999    // Step 2 and 3.a
1000    debug!("phase: load package sources");
1001    // A package whose sources cannot be read is not compiled, and nothing of it is
1002    // published — but the failure is accumulated like any other rather than returned,
1003    // because by the time we get here other packages of the build may already have
1004    // pushed diagnostics onto `errors` and returning would carry this one past the
1005    // reporting loop and drop theirs ("nothing is rendered and then dropped").
1006    //
1007    // A loading error names a path and has no span, so it renders against the shared
1008    // database whether or not this package contributed a single file to it.
1009    //
1010    // The two roots are walked separately, because a module's name is its path under
1011    // its own root. `tests/` is walked only for the package whose tests are being
1012    // compiled, and a package that holds no `tests/` directory at all is a package with
1013    // no tests rather than a failure — unlike `src/`, which every package has.
1014    let load_root = |root: source::SourceRoot, sources: &mut SourceFiles| {
1015        source::load_package_sources_into(&package.root, root, Some(&package.name), sources)
1016    };
1017
1018    let src_ids = match load_root(source::SourceRoot::Src, sources) {
1019        Ok(file_ids) => file_ids,
1020        Err(error) => {
1021            errors.push(error);
1022            return None;
1023        }
1024    };
1025    let test_ids = match tests {
1026        TestRoot::Skipped => Vec::new(),
1027        TestRoot::Compiled => match load_root(source::SourceRoot::Tests, sources) {
1028            Ok(file_ids) => file_ids,
1029            Err(error) => {
1030                errors.push(error);
1031                return None;
1032            }
1033        },
1034    };
1035
1036    // Step 3.b
1037    debug!("phase: parse package sources");
1038    let mut modules: Vec<parser::Module> = vec![];
1039    let mut test_modules: Vec<parser::Module> = vec![];
1040    // Which file each module was parsed from. This is the only point in the compiler
1041    // where both halves are in scope at once — a phase is handed a module and never
1042    // learns where it came from — so the mapping is recorded here and used below to
1043    // wrap the check errors in `InFile`, which is what lets their labels render.
1044    let mut module_files: HashMap<Name, SourceFileId> = HashMap::new();
1045    // Every module this package declares, with the file that declared it. A name two
1046    // files both answer to loses one of them in the map above, so the collision check
1047    // is given this list instead, in the order the roots were walked: `src/` first.
1048    let mut local_modules: Vec<resolve::LocalModule> = vec![];
1049    let mut parse_failures = 0;
1050    for (id, file) in sources
1051        .iter()
1052        .filter(|(id, _)| src_ids.contains(id) || test_ids.contains(id))
1053    {
1054        match parser::parse(file.file()) {
1055            Ok(module) => {
1056                module_files.insert(module.name.clone(), id);
1057                local_modules.push(resolve::LocalModule {
1058                    name: module.name.clone(),
1059                    file: file.package_path(),
1060                });
1061                if test_ids.contains(&id) {
1062                    test_modules.push(module);
1063                } else {
1064                    modules.push(module);
1065                }
1066            }
1067            Err(err) => {
1068                parse_failures += 1;
1069                errors.push(CompilationError::from(err, id));
1070            }
1071        }
1072    }
1073
1074    let parsed = modules.len() + test_modules.len();
1075    if parse_failures == 0 {
1076        print_status(true, format!("parsed {} modules", parsed));
1077    } else {
1078        print_status(
1079            false,
1080            format!(
1081                "parsed {} modules, {} failed to parse",
1082                parsed, parse_failures
1083            ),
1084        );
1085    }
1086
1087    // Step 3.c
1088    // TODO Verify modules name match file system.
1089    // TODO Include this into the parser::parse() function (w/ module name as argument) ?
1090
1091    // `private-modules` can only be checked against the package's real modules once they
1092    // are parsed, which is why this lives here rather than inside `manifest::load` — every
1093    // other manifest error is known from the manifest text alone. What the list is *for*
1094    // is a few lines down: a module it names is kept out of what this package publishes.
1095    //
1096    // It is checked against `src/` alone. The list says what the package does not ship,
1097    // and a test module is not shipped by anything, so naming one there names a module
1098    // this package does not hold — the same answer whether or not the tests are being
1099    // compiled.
1100    //
1101    // A file that failed to parse contributes no module, so with any parse failure the list
1102    // of modules the package holds is known to be short. Checking against it then blames the
1103    // manifest for the parser's failure, and the parse error is already on its way to the
1104    // user, so the check is skipped entirely rather than run on a list it cannot trust.
1105    if parse_failures == 0 {
1106        let held_modules: std::collections::HashSet<&Name> =
1107            modules.iter().map(|m| &m.name).collect();
1108        let missing_private_modules: Vec<manifest::ManifestError> = package
1109            .manifest
1110            .private_modules
1111            .iter()
1112            .filter(|name| !held_modules.contains(name))
1113            .cloned()
1114            .map(|name| manifest::ManifestError::PrivateModuleNotFound {
1115                manifest_path: package.manifest_path(),
1116                name,
1117            })
1118            .collect();
1119        if !missing_private_modules.is_empty() {
1120            errors.push(CompilationError::Manifest(missing_private_modules));
1121        }
1122    }
1123
1124    // Step 3.d: the whole map of module names this package can import, built before
1125    // anything is canonicalized. A name two modules both answer to is the manifest's
1126    // doing, not any one file's, so it is reported here and no module of the package is
1127    // canonicalized, type checked or checked for exhaustiveness
1128    // (`docs/spec/packages.md#two-modules-under-one-name-is-an-error`).
1129    //
1130    // The files have been read and parsed by this point, because `local_modules` is
1131    // taken from the parsed module headers. `SourceFile` derives a module name from the
1132    // relative path alone, so this could run one step earlier, against the walk; the
1133    // reason it does not is that the parsed header is what every other phase calls a
1134    // module by.
1135    //
1136    // Whichever roots this build walked are in that list, because the two share one set
1137    // of names: `src/Model.zel` and `tests/Model.zel` are both `Model`, and the chapter
1138    // calls that the same error as two modules of one root answering to one name
1139    // (`docs/spec/packages.md#source-roots`).
1140    //
1141    // It is not found by the same builds, though. A collision within `src/` fails every
1142    // build; one that spans the roots — and equally one between a `dependencies` module
1143    // and a `test-dependencies` module — is found only when the tests are compiled,
1144    // because that is the only build in which both halves are here to collide. A
1145    // `tests/` root is read [when this package's own tests are run and at no other
1146    // time](../../docs/spec/packages.md#tests), so an ordinary build has not read the
1147    // second file and has nothing to report.
1148    let visible = match resolve::visible_modules(package, &local_modules, &dependencies) {
1149        Ok(visible) => visible,
1150        // As with the uncompiled-dependency arm above, the diagnostic is the whole
1151        // report: a second, shorter copy on the status line said nothing it does not.
1152        Err(collisions) => {
1153            errors.push(CompilationError::Resolution(collisions));
1154            return None;
1155        }
1156    };
1157
1158    // Each dependency's public modules enter the environment under the spelling this
1159    // package names them by, and under no other: a wrapped dependency's `Size` is
1160    // `AcmeWidgets.Size` here and nothing else, an unwrapped one's is `Size` and
1161    // nothing else. The `Interface` is the same either way — it carries the module's
1162    // own name, never the spelling — which is what keeps two packages that spell one
1163    // dependency differently agreeing about every type in it.
1164    let mut interfaces: HashMap<Name, Interface> = HashMap::new();
1165    // A `test-dependency`'s modules are available to `tests/` and to nothing else, so
1166    // they are held back here and added to the environment for the tests pass alone. A
1167    // module of `src/` naming one finds no module of that name.
1168    let mut test_interfaces: HashMap<Name, Interface> = HashMap::new();
1169    let test_only: std::collections::HashSet<&PackageName> = match tests {
1170        TestRoot::Skipped => std::collections::HashSet::new(),
1171        TestRoot::Compiled => package.manifest.test_dependencies.keys().collect(),
1172    };
1173
1174    for (spelling, origin) in &visible {
1175        if origin.package == package.name {
1176            // This package's own modules are inserted by `check_in_order` as each one
1177            // is checked, under the name it declares.
1178            continue;
1179        }
1180
1181        if let Some(interface) = published
1182            .get(&origin.package)
1183            .and_then(|modules| modules.get(&origin.module))
1184        {
1185            if test_only.contains(&origin.package) {
1186                test_interfaces.insert(spelling.clone(), interface.clone());
1187            } else {
1188                interfaces.insert(spelling.clone(), interface.clone());
1189            }
1190        }
1191    }
1192
1193    // Whether this package declares one of the eight default imports, and so receives
1194    // none of them. It is asked here rather than by each root's walker because both
1195    // roots have to get the same answer: a test module is checked against the same
1196    // `Basics` a `src/` module is.
1197    //
1198    // It is asked of `src/` alone, and deliberately. A build that compiles the tests
1199    // and one that does not have to agree about what a `src/` module means, and they
1200    // cannot if a file under `tests/` can move the answer — `tests/List.zel` would make
1201    // this package look like `zelkova-core` to `compile_package_with_tests` and not to
1202    // `compile_package`, so the same `src/` module would resolve `Int` in one build and
1203    // not in the other. `src/` is also the whole of what the exemption is for: it
1204    // exists so that no module of `zelkova-core` can close an implicit import cycle
1205    // (`DEC-17`), and a test module cannot be on such a cycle, because nothing imports
1206    // one.
1207    let package_declares_a_default =
1208        default_imports::declares_a_default(modules.iter().map(|m| &m.name));
1209
1210    // Steps 4 and 5, once per source root. Two passes rather than one walk over both,
1211    // because the two roots are two environments: `src/` is checked knowing nothing of
1212    // `tests/`, and `tests/` is checked against everything `src/` published to this
1213    // package — the private modules included, since `interfaces` holds every module of
1214    // the package and the `private-modules` filter applies only to what is published.
1215    let mut roots: Vec<(source::SourceRoot, &[parser::Module])> =
1216        vec![(source::SourceRoot::Src, &modules)];
1217    if tests == TestRoot::Compiled {
1218        roots.push((source::SourceRoot::Tests, &test_modules));
1219    }
1220
1221    for (root, root_modules) in roots {
1222        if root == source::SourceRoot::Tests {
1223            // A package whose own modules did not check cannot say anything true about
1224            // its tests: every one of them would be blamed for a type the package never
1225            // managed to declare.
1226            if errors.len() != errors_before {
1227                break;
1228            }
1229
1230            interfaces.extend(std::mem::take(&mut test_interfaces));
1231        }
1232
1233        debug!("phase: Build module dependency graph ({})", root);
1234        // A cycle leaves us with no order to check the modules in, so the check phase is
1235        // skipped — but the error goes through the same reporting path as the others
1236        // instead of returning early unrendered.
1237        let walker = match dependencies::ModuleWalker::new_for_root(
1238            root_modules,
1239            &module_files,
1240            package_declares_a_default,
1241        ) {
1242            Ok(walker) => Some(walker),
1243            Err(err) => {
1244                errors.push(err.into());
1245                None
1246            }
1247        };
1248
1249        debug!("phase: Check modules ({})", root);
1250
1251        // Step 5: Follow graph and call check_module on each
1252        if let Some(walker) = walker {
1253            // `check_in_order` checks every module regardless of earlier failures and
1254            // hands back both halves: the modules that checked, and the errors from the
1255            // ones that didn't (see `docs/tickets/README.md`, `BUG-2`). Both are reported
1256            // here, and the errors still flow into `errors` below so a failing module
1257            // keeps making this function return `Err` — only the previously-discarded
1258            // successes are new.
1259            //
1260            // `module_files` is also how each checked module's `Interface` learns which
1261            // file it came from (`Interface::file`, `ERR-5`): this is the one place that
1262            // knows both the module and its file, so `check_in_order` takes the map and
1263            // stamps it onto every interface it inserts as it goes.
1264            let (can_mods, check_errors) =
1265                walker.check_in_order(&package.name, &mut interfaces, &module_files, check_module);
1266
1267            let what = match root {
1268                source::SourceRoot::Src => "modules",
1269                source::SourceRoot::Tests => "test modules",
1270            };
1271
1272            if check_errors.is_empty() {
1273                print_status(
1274                    true,
1275                    format!(
1276                        "checked {}: {:#?}",
1277                        what,
1278                        can_mods
1279                            .iter()
1280                            .map(|m| m.canonical.name.as_human_string())
1281                            .collect::<Vec<_>>()
1282                    ),
1283                );
1284            } else {
1285                print_status(
1286                    false,
1287                    format!(
1288                        "checked {}: {:#?} ({} failed to check)",
1289                        what,
1290                        can_mods
1291                            .iter()
1292                            .map(|m| m.canonical.name.as_human_string())
1293                            .collect::<Vec<_>>(),
1294                        check_errors.len()
1295                    ),
1296                );
1297                // Tag each error with the file its module was read from, so the spans its
1298                // phase produced have something to point into. A module with no entry —
1299                // there is none today, since only a module that parsed can be checked —
1300                // stays unwrapped and renders exactly as it did before spans existed.
1301                errors.extend(check_errors.into_iter().map(|error| {
1302                    match error.module().and_then(|name| module_files.get(name)) {
1303                        Some(id) => CompilationError::InFile(Box::new(error), *id),
1304                        None => error,
1305                    }
1306                }));
1307            }
1308        }
1309    }
1310
1311    if errors.len() != errors_before {
1312        return None;
1313    }
1314
1315    // Step 6: what this package offers whoever depends on it. Every module of `src/`
1316    // except the ones `private-modules` names and every `module foreign` facade, which
1317    // is package-internal by its own declaration whatever the manifest says
1318    // (`docs/spec/packages.md#what-a-package-exposes`, `docs/spec/interop.md`). A name
1319    // that would have reached one of those is simply absent from a dependent's map, so
1320    // it fails there as a module that does not exist.
1321    let facades: std::collections::HashSet<&Name> = modules
1322        .iter()
1323        .filter(|module| module.binding_foreign)
1324        .map(|module| &module.name)
1325        .collect();
1326    let private: std::collections::HashSet<&Name> =
1327        package.manifest.private_modules.iter().collect();
1328    // A module of `tests/` is not part of what the package ships, and nothing outside
1329    // the package can observe that it exists at all.
1330    let test_module_names: std::collections::HashSet<&Name> =
1331        test_modules.iter().map(|module| &module.name).collect();
1332
1333    let public = interfaces
1334        .into_iter()
1335        // The map still holds the dependencies' interfaces seeded above; a package
1336        // publishes its own modules and nothing else, which is what stops it
1337        // re-exporting a dependency's module as one of its own
1338        // (`docs/spec/packages.md#what-a-package-boundary-cannot-rename`).
1339        .filter(|(name, interface)| {
1340            interface.module_name.package == package.name
1341                && !facades.contains(name)
1342                && !private.contains(name)
1343                && !test_module_names.contains(name)
1344        })
1345        .collect();
1346
1347    Some(public)
1348}

1350/// Take a parsed module file within the ecosystem and apply all checks to it
1351///
1352/// TODO canonicalization must happens before checkings, because type check (at least)
1353/// will require access to other modules canonical representation.
1354/// That probably mean moving the `canonical::canonicalize` call out of this function
1355///
1356/// `package_declares_a_default` says whether the package `source` belongs to
1357/// declares one of the eight [default
1358/// imports](default_imports) — see [`default_imports::declares_a_default`].
1359/// `dependencies::ModuleWalker` computes it once, from the same module list it
1360/// builds the import graph from, and hands it to every module it checks through
1361/// this same parameter, which is why `check` in
1362/// [`ModuleWalker::check_in_order`](dependencies::ModuleWalker::check_in_order)
1363/// carries it too: `check_module` is normally reached only as that `fn` pointer.
1364pub fn check_module(
1365    package: &PackageName,
1366    interfaces: &HashMap<Name, Interface>,
1367    source: &parser::Module,
1368    package_declares_a_default: bool,
1369) -> Result<CheckedModule, CompilationError> {
1370    // - desugar ~?~ *!*
1371    // Should I have an intermediate AST before type checking ?
1372    // This could actually be useful to have something optimized for
1373    // the type checker. It would also be something that can be used
1374    // as an information dump for dependencies (keep types solved as
1375    // a result and don't type checks those modules more than once).
1376    //
1377    // Each phase accumulates its own errors and hands back all of them; this is where
1378    // they are tagged with the module they came from, because a phase only ever sees
1379    // one module and has no reason to carry its name around.
1380    let canonical =
1381        canonical::canonicalize(package, interfaces, source, package_declares_a_default)
1382            .map_err(|errors| CompilationError::Canonical(errors, source.name.clone()))?;
1383
1384    // - type checking and inference
1385    //
1386    // The typer answers with the types it solved — one `ir::Solved` per declaration,
1387    // carrying a type on every node of the ones it could type and saying why for the
1388    // ones it could not. Not logged on the way out: `infer_annotated` already dumps each
1389    // declaration's term under `debug`, and `typer::type_check` is `pub`, so a test that
1390    // wants the map calls it directly. It reads the same interfaces canonicalization
1391    // resolved this module's imports against, for the types of what they declare.
1392    let solved = typer::type_check(&canonical, interfaces)
1393        .map_err(|errors| CompilationError::Type(errors, source.name.clone()))?;
1394
1395    // verify in pattern matching branches that all variants are covered
1396    exhaustiveness::check(&canonical)
1397        .map_err(|errors| CompilationError::Exhaustiveness(errors, source.name.clone()))?;
1398
1399    // - the shape a backend reads. Built here because this is the last frame holding
1400    // both the canonical module and what the typer solved from it, and nothing after
1401    // this point needs either half separately.
1402    let ir = ir::build(&canonical, solved);
1403
1404    Ok(CheckedModule { canonical, ir })
1405}

1407/// One module that passed every check, in both the forms the compiler still needs it.
1408///
1409/// The two halves answer different questions and neither is derivable from the other.
1410/// [`canonical`](Self::canonical) is what an [`Interface`] is built from, so the modules
1411/// that import this one are checked against it; [`ir`](Self::ir) is what a backend
1412/// reads, and carries the solved types, the name kinds, the arities and the constructor
1413/// positions that emission needs and name resolution never did.
1414#[derive(Debug)]
1415pub struct CheckedModule {
1416    pub canonical: canonical::Module,
1417    pub ir: ir::Module,
1418}
1419
1420impl CheckedModule {
1421    /// This module's [`Interface`] — [`canonical::Module::to_interface`], which is the
1422    /// half of a checked module that crosses a module boundary.
1423    ///
1424    /// Inherent so that a caller holding a `CheckedModule` reaches it without importing
1425    /// [`Checked`]; the body is that trait's, so there is only one to keep correct.
1426    pub fn to_interface(&self, file: Option<SourceFileId>) -> Interface {
1427        Checked::to_interface(self, file)
1428    }
1429}
1430
1431/// What [`dependencies::ModuleWalker::check_in_order`] needs of whatever its checker
1432/// hands back: a name to key the module by, and the interface the modules after it are
1433/// checked against.
1434///
1435/// It is a trait because the walker drives more than one checker. The compiler's is
1436/// [`check_module`], which answers with a [`CheckedModule`]; `tests/spec.rs` drives the
1437/// same walker with a checker that only canonicalizes, because a spec example is judged
1438/// on the errors each phase reports and there is nothing to emit from it.
1439pub trait Checked {
1440    /// The module's own name, package included.
1441    fn name(&self) -> &ModuleName;
1442
1443    /// The trimmed-down view the modules that import this one are checked against.
1444    ///
1445    /// `file` is where this module was read from, when the caller knows it — see
1446    /// [`Interface::file`].
1447    fn to_interface(&self, file: Option<SourceFileId>) -> Interface;
1448}
1449
1450impl Checked for canonical::Module {
1451    fn name(&self) -> &ModuleName {
1452        &self.name
1453    }
1454
1455    fn to_interface(&self, file: Option<SourceFileId>) -> Interface {
1456        canonical::Module::to_interface(self, file)
1457    }
1458}
1459
1460impl Checked for CheckedModule {
1461    fn name(&self) -> &ModuleName {
1462        &self.canonical.name
1463    }
1464
1465    fn to_interface(&self, file: Option<SourceFileId>) -> Interface {
1466        self.canonical.to_interface(file)
1467    }
1468}
