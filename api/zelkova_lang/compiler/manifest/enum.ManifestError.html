Expand description

Every way reading a manifest can fail.

Like SourceFileError, a manifest error has no Span to render: the location it would want is a byte range in zelkova.toml, which is not a file the Files database holds. Every variant therefore carries the manifest_path it was found in, so that its message can name the file on its own — which is the whole of the location a reader gets, and is why every variant but PrivateModuleNotFound goes back to the caller unrendered, the same way loading errors already do.

PrivateModuleNotFound

private-modules names a module this package does not hold.

Unlike every other variant here, this one cannot be raised by load: knowing what the package holds needs its sources loaded, which happens only after the manifest has already been accepted. compile_package builds this once it has parsed every module, and folds it into the normal per-package error accumulation rather than the unrendered path the rest of this enum takes.
